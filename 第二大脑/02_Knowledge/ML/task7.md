# 二、5–20分钟：核心概念

## 2.1 缺失值：为什么传感器会产生 NaN？

### 生活类比

假设老师统计全班考试成绩：

|学生|数学成绩|
|---|---|
|A|90|
|B|85|
|C|未记录|
|D|95|

学生C的成绩没有记录。

能不能认为他的成绩是0？

不能。

**没有记录，不等于实际数值为0。**

机器人传感器也是一样。

例如：

```
ESP32
  │
  ├── PWM = 120
  ├── Voltage = ?
  └── RPM = 100
```

电压缺失可能是通信失败、解析错误或采样失败。

它并不意味着电池电压为0V。

在 pandas 中，数值缺失通常可以用 `NaN` 表示。

### 如何检测缺失值？

```
df.isna()
```

返回一个布尔表格。

```
df.isna().sum()
```

统计每一列有多少个缺失值。

例如：

```
pwm          0
voltage_v    2
rpm          1
```

表示电压有2个缺失值，转速有1个缺失值。

### 如何处理缺失值？

主要有两种基本方法。

**方法A：删除记录**

```
df.dropna()
```

默认删除包含缺失值的行。

优点是简单。

缺点是可能丢失大量有效信息。

例如一条记录只有电压缺失，但 PWM 和 RPM 都正常，直接删除可能有些浪费。

**方法B：填补缺失值**

例如使用中位数：

```
median = df["voltage_v"].median()

df["voltage_v"] = df["voltage_v"].fillna(median)
```

假设有效电压为：

\[ [7.0,\ 7.2,\ 7.4] \]

中位数为：

\[ \boxed{7.2} \]

我们就可以暂时用7.2填补缺失电压。

但要注意：**填补值只是估计，不代表真实测量结果。**

而且如果用于机器学习评估，填补所需的中位数必须只根据训练数据计算。

今天的代码会使用 sklearn 的 `SimpleImputer` 自动完成这一过程。

## 2.2 异常值：为什么不能看到9999就直接删除？

假设记录：

```
PWM = 200
RPM = 9999
```

你可能会认为：

“这个数据太离谱了，删除！”

但机器学习中的异常值需要分情况。

### 第一种：明显无效的测量

例如电池电压：

```
Voltage = -2V
```

对于一个正常工作的、以正电压记录供电状态的2S电池测量系统，这显然不符合预期。

可能是传感器故障、解析错误或数据损坏。

### 第二种：真实但罕见的情况

例如机器人发生碰撞时，电机电流突然增加。

```
正常电流：0.4A
碰撞电流：1.5A
```

1.5A可能比正常数据大很多。

但它也可能是真实的异常工况。

如果你正在训练**机器人故障检测模型**，这类数据反而非常重要。

所以：

\[ \boxed{\text{统计异常}\neq\text{一定是错误数据}} \]

### 数学直觉：Z-score

一种常见的异常检测方法是标准分数：

\[ z=\frac{x-\mu}{\sigma} \]

其中：

- \(x\)：当前测量值
- \(\mu\)：数据均值
- \(\sigma\)：数据标准差

它衡量一个数据距离平均值有多少个标准差。

例如：

\[ \mu=100,\qquad \sigma=10 \]

某次测量：

\[ x=130 \]

则：

\[ z=\frac{130-100}{10}=3 \]

意味着这个值距离平均值3个标准差。

但是，`|z|>3` 并不意味着一定要删除。这个规则依赖数据分布，而且均值和标准差本身也可能受到极端值影响。

今天我们暂时不使用 Z-score 自动删除数据，而是使用**事先定义的模拟传感器有效范围**处理明显无效的读数。

## 2.3 重复数据：为什么要区分重复记录和重复实验？

假设：

```
session=1, PWM=120, RPM=100
session=1, PWM=120, RPM=100
```

可能是同一条记录被程序重复保存了两次。

但也可能是同一实验条件下，真实进行了两次测量，而且结果恰好相同。

因此，**两行数值相同，不一定代表重复采集错误。**

实际工程中，最好同时记录：

```
session_id
sample_id
timestamp_ms
```

这样可以判断是否为同一个采样事件。

今天为了简化实验，我们人为复制一条完整记录，确保它确实是重复保存的数据，再使用：

```
df.drop_duplicates()
```

将其删除。

## 2.4 数据清洗与数据泄漏的关系

这是今天最需要掌握的工程原则。

回顾 Task 004：

```
原始数据
   │
   ▼
训练集 / 测试集
   │
   ├── 训练集
   │      │
   │      ▼
   │   计算填补中位数
   │      │
   │      ▼
   │   训练模型
   │
   └── 测试集
          │
          ▼
     使用训练集的中位数
          │
          ▼
       测试模型
```

错误做法：

```
median = df["voltage_v"].median()
```

然后才划分训练集和测试集。

因为这个中位数包含测试数据的信息。

正确做法是让 `SimpleImputer` 和模型一起放进 `Pipeline`。

这样在交叉验证或训练时，填补器只会根据当前训练数据计算统计量。

另外，事先定义的物理有效范围与从数据中学习的统计阈值不同。前者可以作为固定的数据质量规则；后者必须避免利用最终测试集来拟合。

# 四、逐段理解最重要的代码

## 4.1 为什么使用 `drop_duplicates()`？

```
clean = raw.drop_duplicates().copy()
```

`drop_duplicates()` 会根据行中的全部字段识别完全重复的记录。

今天我们明确知道其中一行是人为重复复制的，因此可以删除。

但真实机器人日志中，应该优先根据唯一采样ID、时间戳和实验轮次判断是否重复，而不是盲目删除数值相同的记录。

## 4.2 为什么无效电压变成 NaN，而不是删除整行？

```
clean.loc[    bad_voltage,    "voltage_v"] = np.nan
```

因为这条记录中的其他字段可能仍然有效。

例如：

```
PWM = 120
Voltage = -2
Current = 0.3
RPM = 100
```

电压不可信，但 PWM、Current 和 RPM 可能是正常记录。

所以我们只把无效电压标记为缺失。

后续再通过训练集统计量填补。

这种方法能保留更多信息，但填补是否合理仍需结合传感器故障原因判断。

## 4.3 为什么缺失 RPM 的记录被删除？

因为今天的任务是监督回归：

\[ X=[PWM,Voltage,Current] \]\[ y=RPM \]

模型训练需要真实标签。

如果 RPM 缺失，就无法直接计算该样本的监督回归损失。

因此本实验删除缺失目标值的记录。

这并不意味着所有机器学习任务都必须删除缺失标签。半监督学习等方法可以利用未标注样本，但不属于今天的范围。

## 4.4 为什么使用 `GroupShuffleSplit`？

我们以前使用：

```
train_test_split()
```

随机划分数据。

但是机器人采集的数据经常存在相关性。

例如同一轮电机实验：

```
Session 1
  ├── PWM=60
  ├── PWM=90
  ├── PWM=120
  └── PWM=150
```

这些数据共享相同的实验条件。

因此，我们希望：

**同一实验轮次的数据只能出现在训练集或测试集中的一个集合。**

```
splitter = GroupShuffleSplit(    n_splits=1,    test_size=2,    random_state=42)
```

这里的 `test_size=2` 表示留出2个实验轮次，而不是2条数据。

因为我们有6个不同的 Session。

最后得到4轮训练、2轮测试。

需要注意：`GroupShuffleSplit` 并不会自动处理时间先后关系。如果目标是预测未来时间段，还需要考虑时间顺序。

## 4.5 Pipeline 为什么能防止数据泄漏？

```
model = make_pipeline(    SimpleImputer(strategy="median"),    StandardScaler(),    LinearRegression())
```

观察数据流：

```
X_train
   │
   ▼
SimpleImputer
学习训练集各列中位数
   │
   ▼
StandardScaler
学习训练集均值和标准差
   │
   ▼
LinearRegression
学习模型参数
   │
   ▼
训练完成
```

测试时：

```
X_test
   │
   ▼
使用训练集学到的中位数填补
   │
   ▼
使用训练集学到的均值和标准差
   │
   ▼
线性回归模型预测
```

这里最重要的区别是：

```
model.fit(X_train, y_train)
```

和：

```
model.predict(X_test)
```

`fit()` 会学习预处理参数和模型参数。

`predict()` 只应用已经学到的规则，不会重新拟合填补器和标准化器。

# 五、35–40分钟：常见错误与自测

## 5.1 三个常见错误

**错误一：把 NaN 当成0。**

```
df.fillna(0)
```

虽然代码能够运行，但不一定合理。

缺失电压不代表电压为0。

**错误二：把所有极端值都删除。**

例如电机碰撞时出现较大电流。

这可能正是故障检测模型需要学习的关键样本。

**错误三：提前使用全部数据计算中位数。**

```
median = X["voltage_v"].median()
```

如果 X 包含最终测试集，就可能造成数据泄漏。

更规范的方法是使用 `SimpleImputer` 和 `Pipeline`。

应使用分组划分，避免同一轮实验跨集合出现。

需要先判断这些记录是真实碰撞事件还是测量错误。

# 六、联系机器人项目与后续生成式AI

今天的知识并不只用于线性回归。

未来你的 ROS2 AI Vision Rover 可能同时采集：

```
Camera
  │
  ├── 图像
  ├── 时间戳
  └── 检测结果

IMU
  │
  ├── 加速度
  └── 角速度

Encoder
  │
  └── 轮速

  │
  └── PWM控制量
```

这些数据可能存在：

- 某些时间戳缺少传感器数据；
- 摄像头和 IMU 的采样频率不同；
- 编码器计数异常；
- 重复记录；
- 不同传感器之间的时间不同步。

这些问题需要在传感器融合、状态估计和机器人学习之前处理。

以后学习 VAE、Diffusion Policy、LeRobot 时，也会遇到数据质量问题。

例如模仿学习中的一条轨迹：

```
Observation_t
      │
      ▼
Action_t
      │
      ▼
Observation_t+1
```

如果动作与观测时间戳没有对齐，模型就可能学习到错误的动作对应关系。

所以，**数据清洗是机器学习系统可靠性的基础，而不是可有可无的准备步骤。**
