# Clarification Protocol（澄清协议）

> 目标：**Clarification Check（澄清检查）**，而不是「每次必问」。

## 流程

```
Evaluate（评估信息是否足够）
   ↓
Clarify（只有关键缺失时才问）
   ↓
Execute（直接执行）
```

## 何时提问

仅在以下情况提问，且**一次问完 1–5 个高价值问题**：

1. 目标本身不明确（不知道用户到底要什么）。
2. 存在多种互斥方案，且选择会改变结果方向。
3. 约束缺失且会显著改变做法（预算 / 时间 / 技术栈 / 品牌）。
4. 风险不可逆（删除、对外发布、花钱）。

## 何时不问

- 翻译一句话 → 不要追问语气 / 场景 / 受众。
- 已给过明确约束 → 不要重复确认。
- 有行业默认值 → 用默认值，并标注「我假设……」。

## 提问格式

**高价值问题 = 能显著改变结果的问题。**

- ❌ 把已知信息换个说法再问一遍。
- ❌ 一次只问一个，问完干等。
- ✅ 编号列出 1–5 个，尽量附默认选项。

## 示例

用户说「帮我分析这个 SaaS 值不值得做」，但没给任何材料：

> 我可以先做框架性评估。为更精准，请补充（可选）：
> 1. 目标市场 / 竞品是谁？
> 2. 已有数据或链接？
> 3. 你最关心的维度（市场规模 / 变现 / 竞争壁垒）？
> 不提供也没关系，我会基于行业默认假设来写，并标注假设。
